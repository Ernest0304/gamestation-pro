# IT Audit — Full state (commit 61e15f0)

## Severity 1 — data corruption / security / financial loss

**S1-1. Order creation is NOT atomic — orphan orders on item-insert failure.**
`store.js:996-1002` inserts `orders`, then separately inserts `order_items`. If the second call fails, the order persists `status='completed'` with zero line items: Z-Report counts revenue while the kitchen sees nothing. Wrap both in a `create_order_atomic` RPC (same pattern as `apply_balance_delta`).

**S1-2. `closeSession` lacks the atomic status guard, allowing double-debit.**
`store.js:553` runs the close UPDATE without `.eq('status','active')` — the guard already used in `extendWalkIn` (line 506-507). Two concurrent clicks pass the in-memory check (line 524), both call `chargeBalance` (line 562), and the member is debited twice. Add the filter and short-circuit when `data.length === 0`.

**S1-3. RLS grants authenticated users full DELETE on all tables.**
Every policy (`002:53`, `003:87-94`, `004:71`) is `FOR ALL USING (auth.role()='authenticated')`. A leaked staff login can `DELETE FROM members` from DevTools. Split into SELECT/INSERT/UPDATE policies; gate DELETE behind service-role RPCs.

**S1-4. Station status drifts on `closeSession` partial failure.**
`store.js:582` updates `stations.status='idle'` with no error check. If the UPDATE fails, the session closes (revenue counted) but the dashboard shows the station active forever. Derive station status from active-session count on render instead.

## Severity 2 — functional bug, daily-use issue

**S2-1. Realtime member-archive filter never fires.**
`store.js:305` checks `m.archived_at`, but `memberToApp` (lines 60-73) never maps that column. The check is permanently `undefined`; archived members stay visible until full reload. Add `archivedAt: row.archived_at` to the mapper.

**S2-2. Discount audit log records duplicated shape.**
`store.js:1012` spreads raw `discountInput` into `after_state`. POS sends `{ type, value, reason, amount }` (`pos.js:652`), so the audit row carries both `value` AND `amount`. Normalize before logging.

**S2-3. `_warned` set grows unboundedly across the day.**
`dashboard.js:148-149` adds entries forever; pruning at line 164-170 only catches sessions still in cache. Add a 24h TTL.

**S2-4. Cash modal `min` uses unrounded `totalDue`.**
`pos.js:701` sets `min="${totalDue}"`. Compounded rounding can leave `12.345`, the browser validator may then reject `12.35`. Use `.toFixed(2)`.

**S2-5. `_initPromise` reused on retry without freshness check.**
`store.js:225-233` caches the in-flight init. Correct for timeout-retry, but a stale promise from a rotated auth token can resolve into the new session. Discard if older than ~30s.

**S2-6. Cart `unitPrice` snapshot diverges from menu-grid re-read.**
`pos.js:46-54` snapshots `unitPrice` at add-time; the grid re-reads `i.price` per render (`pos.js:127`). If a realtime price update hits mid-checkout, cart total and displayed price disagree.

## Severity 3 — edge case / code smell

**S3-1.** Discount numpad accepts `200%` until the preview-update validates (`pos.js:507-516`); validate per keystroke. **S3-2.** `chargeBalance` writes the cache (`store.js:668`) bypassing the realtime path used elsewhere — works, but inconsistent. **S3-3.** Magic numbers `10000` (`app.js:155`), `8000` (`auth.js:54`), `12000` (`auth.js:84`), `6000` (`app.js:259`) — extract a `GC.TIMEOUTS` map. **S3-4.** Audit-log inserts are best-effort with no retry (`store.js:796, 816, 839, 1015`) — a failing audit silently loses the trail. **S3-5.** `order_items.menu_item_id ON DELETE SET NULL` (`003:62`) is fine because rows snapshot `name_zh`/`menu_no`, but flag for ops. **S3-6.** `todayRevenue()` (`dashboard.js:52`) re-filters all sessions every render — memoize once per minute.

## For upcoming Z-Report — data model recommendation

Record the close **event** with a frozen snapshot — don't pre-aggregate.

```
daily_close (
  id UUID PK, business_date DATE UNIQUE, closed_at TIMESTAMPTZ,
  closed_by TEXT, opening_float NUMERIC,
  expected_cash NUMERIC, counted_cash NUMERIC, variance NUMERIC,
  gaming_revenue NUMERIC, fb_revenue NUMERIC, topup_revenue NUMERIC,
  void_count INTEGER, discount_total NUMERIC,
  payment_breakdown JSONB,   -- {cash, paynow, member_balance, card}
  notes TEXT
)
```

Single RPC `close_business_day(date, counted_cash, float, notes)` selects from `sessions`+`orders`+`top_ups` within `[date+06:00, +24h)` (cafe runs past midnight). The RPC also stamps `closed_business_date` on `orders`/`sessions`; when non-null, `voidOrder` is blocked and voids become adjustment rows, preserving Z-Report immutability.

## For upcoming split bill — schema recommendation

`orders.payment_method` already has the `'mixed'` enum (`003:47`). Add:

```
order_payments (
  id UUID PK, order_id UUID FK orders ON DELETE CASCADE,
  method TEXT CHECK (method IN ('cash','paynow','member_balance','card')),
  amount NUMERIC NOT NULL,
  member_id UUID NULL,           -- only when method='member_balance'
  cash_received NUMERIC NULL, change_given NUMERIC NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
)
```

A trigger enforces `SUM(order_payments.amount) = orders.total` once `orders.status='completed'`, and auto-sets `payment_method='mixed'` when more than one row exists. Single-method orders still insert one row, so reports always read `order_payments` — never `orders.payment_method`. Each `member_balance` row drives one `chargeBalance` call, keeping the audit RPC as the single source of truth. UI loops the cash modal until remaining balance hits zero.
