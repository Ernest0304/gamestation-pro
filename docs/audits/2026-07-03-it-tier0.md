# IT Audit — 2026-07-03 (commit a29d68a, Tier 0 batch)

Scope: the 9-item Tier 0 commit only. Business-day math verified correct: `getBusinessDate` (store.js:704) and `businessDayWindow` (store.js:711) agree at the exact 06:00:00 SGT boundary (half-open window, 06:00 starts the new day), are device-TZ independent (epoch + `toISOString` / explicit `+08:00` parse), use server-synced `now()`, and SGT has no DST. No bug found.

## 🔥 Severity 1

1. **Void refund-row insert failure is swallowed** — store.js:1984, store.js:2061. Order/session is already marked voided (store.js:1965/2042) before the negative tender insert; on insert error only `console.error` fires. Result: void succeeded, drawer expectation silently overstated on refund day; cashier never told, no retry. Fix: toast + block, or move status+refund into one RPC (atomic).
2. **Cross-register double-void race** — idempotency guard is client-cache only (store.js:1932) and the status update is unconditional (store.js:1965). Two devices voiding the same order both pass → member balance credited twice (`chargeBalance` RPC, store.js:1946) and duplicate negative tender rows. Fix: `.update(...).eq('status','completed').select()` and abort on 0 rows.
3. **Offline guard bypasses** — CSS blocklist (style.css:160-163) misses: cash-modal confirm and PayNow/member `GC.confirm` (pos.js:840-852, reachable if offline hits after the pay tile), the entire member top-up flow (members.js:376+ — money-taking, unblocked), and keyboard activation (`pointer-events:none` doesn't stop Tab+Enter on laptops).

## 🟠 Severity 2

4. **Stale member crash** — pos.js:846 `getMember(selectedMemberId).name` unguarded; localStorage restore (pos.js:105) can resurrect a deleted member ID → TypeError at checkout.
5. **PIN hash trivially crackable** — unsalted sha256 of 4-8 digits (settings.js:245), hash readable by any staff client (`getSettings().managerPin`). ≤10⁸ candidates cracks in seconds offline. Acceptable only as documented deterrence; recommend server-side RPC verify + salt, and never reuse this PIN elsewhere.
6. **PIN gate bypass via localStorage** — editing `yxd_pos_cart_v1` injects a 100% `discount` without the modal-time check (pos.js:810).
7. **xlsx 0.18.5 vendored** with known CVEs (CVE-2023-30533, CVE-2024-22363). Export-only today (history.js:283) so low exposure; upgrade to 0.20.2+.
