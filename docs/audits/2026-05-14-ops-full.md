# Operations Audit — Full state (commit 61e15f0)

Lens: tired Friday-night cashier, 3 walk-ins waiting, members at gaming,
desserts ringing in. What breaks before Z-Report and split-bill ship?

## Operational risks (revenue loss / customer complaints)

1. **`cashier` column exists but is never populated.** `store.js:993`
   writes `cashier: cashier || null`, but `pos.js:647-654` checkout call
   doesn't pass it. `store.js:openSession` has no actor field at all.
   Z-Report cannot answer "who closed which drawer?"
   `supabase.auth.getUser()` already works (used in `store.js:789`) —
   wire it into every order + session write.

2. **Member balance shortfall silently logged, never shown.**
   `store.js:563-571`: when balance runs out mid-session, close succeeds,
   `audit_log` notes "cashier should collect difference", but the close
   modal (`dashboard.js:592-645`) shows the discounted total and a
   normal toast. Cashier doesn't know. Revenue leaks.

3. **No idempotency on checkout.** `pos.js:317-319` pay buttons aren't
   disabled during async `createOrder`. Double-tap on slow Wi-Fi = two
   orders + double-deduct on member balance. `dashboard.js:486-487`
   already handles this for Open Table.

## Process gaps

1. **No shift / drawer concept.** No `shifts` table, no Open/Close
   Drawer, no opening-float. Z-Report needs `shifts(cashier, start_at,
   end_at, opening_float, declared_cash)` for reconciliation. Without
   it, cash totals die on midnight overruns or mid-day cashier swaps.

2. **Sessions outlive a "day".** Walk-in 23:30 → 00:30. `dashboard.js:52`
   `todayRevenue()` uses `endTime ≥ midnight` so it counts in the wrong
   day. Pick a business-day cutoff (e.g. 04:00) or shift cutoff.

3. **No "force close all active" tool.** Staff forget 2 stations →
   timers tick forever (`dashboard.js:320-355`). Need manager-gated
   close-all, or auto-close past N hours.

4. **Receipts vanish after dismissal on PayNow / member-balance.** Add
   a print button to `orders.js:151-176` detail modal — data is there.

5. **No void/refund for gaming sessions.** F&B has it
   (`orders.js:181-195`). Mirror it: status='voided', refund balance,
   audit log.

## Quick wins

1. **Pass `actor_email` into every write.** Stash on `GC._currentUser`
   at boot, pass into `pos.js:647` and `dashboard.js:491-510`.

2. **Disable pay buttons during checkout.** Three lines in
   `pos.js:checkout()` — disable at top, restore in `catch`.

3. **Block close on member shortfall.** In `dashboard.js` member-close,
   if `charge.shortfall > 0`, pop "请收现金 $X" modal before the toast.

4. **Persist cart to `localStorage` on mutation.** `pos.js:11` is
   in-memory; mirror `dashboard.js:19-26`. Browser crash = lost cart.

## Z-Report workflow recommendation (must-have content)

1. **Header**: shop, business date, shift window, cashier email(s),
   opening float.
2. **Cash reconciliation**: expected = float + Σ cash orders − refunds +
   collected shortfalls. Actual counted (input). Variance traffic-light
   (green ≤$2, amber ≤$10, red >$10).
3. **Payment breakdown**: count + $ for Cash / PayNow / Member /
   Voided. Tag Member as "no cash movement" so accountant doesn't
   double-count.
4. **Gaming vs F&B split**: sessions revenue vs orders revenue
   (currently blended in `dashboard.js:todayRevenue`).
5. **Discounts & comps**: list `orders.discount > 0` with reason;
   exclude auto tier discounts; flag manual `comp/staff/complaint`.
6. **Open items at close**: force close-or-ack every `active` session
   before the PDF generates. Prevents "forgot to close" bug.

## Split bill workflow recommendation

Third button in `.pos-pay-options` (`pos.js:241-250`) — `🔀 拆账 /
Split`. Same modal pattern as `showCashModal` (`pos.js:669-795`).

1. Header: `应收 / Total: $X.XX` (read-only).
2. Row 1 — Cash: numpad + presets (current cash modal).
3. Row 2 — PayNow: numpad, no presets (exact-match).
4. Live tally: `已付 = $A + $B = $C` and `差额 = $X − $C`. Confirm
   disabled until `$C ≥ $X`. Overpayment = cash change.
5. Write `payment_method='mixed'` (already in `orders.js:23`),
   structured note `split: cash=$X paynow=$Y change=$Z` for Z-Report.
6. Optional row 3 if member selected: 会员余额 $Y.
