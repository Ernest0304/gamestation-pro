# IT Audit — 2026-05-14 (branding swap, commit 5ebaeff)

## 🔥 Severity 1 — (corrupts data / security / hard fail)
None. Branding is safe to ship as-is.

## 🟠 Severity 2 — (functional bug, daily-use issue)

1. **`theme-color` meta tag not updated** → `index.html:6` still has `<meta name="theme-color" content="#06b6d4">` (cyan), but `manifest.json:8` is now `#7a0818` (burgundy). Repro: open site in mobile Chrome — address-bar tint is cyan; install as PWA — chrome is burgundy. Fix: change `index.html:6` to `content="#7a0818"`.

2. **Dead `body.pos-mode .nav-brand svg` selector** → `css/pos.css:29-31` styles inline `<svg>` color, but the navbar logo is now an `<img>` tag (`index.html:20`). `<img>` cannot be re-tinted via `color` — selector matches nothing. Not a bug today, but it's misleading and the burgundy `<text fill="#7a0818">` inside the SVG is fixed regardless of theme. Fix: delete rule, or convert `nav-logo` back to inline SVG if theme-tinting is desired.

3. **`.brand-accent` still cyan** → `css/style.css:81` defines `.brand-accent { color: var(--cyan) }`. Used in `auth.js:15` next to the burgundy logo — login page shows "郁香潭 · **Yuu Xiang Dam**" with the EN portion in cyan, clashing with the brand. Fix: change to `#7a0818` or remove and let h1 inherit.

## 🟡 Severity 3 — (edge case / cosmetic / code smell)

1. **iOS home-screen icon** → `manifest.json:9-15` declares a single SVG icon. iOS Safari does not reliably render SVG home-screen tiles; user typically sees a generated screenshot. Add `apple-touch-icon` PNG (180×180) and `192×192` + `512×512` PNGs in manifest for parity with Android.

2. **No `<img>` 404 fallback** → if `/img/logo.svg` 404s, navbar (`index.html:20`) and login (`auth.js:14`) show the browser's broken-image icon. Cosmetic only since the SVG is in-repo, but `onerror="this.style.display='none'"` is a one-line defence.

3. **`manifest.json` not query-versioned** → CSS/JS are `?v=14`, manifest is not. Already-installed PWAs keep the old "GameStation Pro" name + cyan theme until OS re-fetches. Low impact (few installs expected pre-launch). Worth bumping `manifest.json?v=14` in `index.html:12`.

4. **CJK font reliance in SVG** → `img/logo.svg:18,31,38,42` references `'STKaiti', 'Songti SC', 'SimSun'`. Non-Chinese-locale iPads (Australia stores) render with system CJK fallback — glyphs appear but stroke style differs from intended brush-serif. Embed as `<path>` or use a webfont if exact rendering matters.

5. **`brand-accent` is a "legacy class" per comment** → `style.css:80` comment says "kept for older modals" but `auth.js:15` actively uses it on the login page. Either treat it as live and re-style, or replace the usage and delete the rule.

## ⚙️ Infrastructure suggestions

1. **Add PNG icon set** → 192/512 PNG + 180 apple-touch-icon. Resolves Sev-3 #1 and future-proofs Android adaptive icons. ~5 min in any SVG-to-PNG tool.

2. **Add Vercel cache headers for `/img/*`** → SVG can be cached aggressively (`Cache-Control: public, max-age=31536000, immutable`) since file path identifies content. If the SVG is later replaced, rename to `logo-v2.svg` rather than overwriting.

3. **Lock down SVG MIME at edge** → confirm Vercel serves `/img/logo.svg` with `Content-Type: image/svg+xml`. If misconfigured (e.g. `text/plain`), the `<link rel="icon" type="image/svg+xml">` will be ignored by some browsers.
