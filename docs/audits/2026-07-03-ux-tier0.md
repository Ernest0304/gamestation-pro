# UX Audit — 2026-07-03 (commit a29d68a, Tier 0 batch)

Scope: cashier-facing UI added in this commit, audited as a busy Chinese-speaking cashier on iPad. Prior-audit (2026-05-14) items not re-flagged.

## ⭐ Critical (blocks daily use) — max 3

1. **Cart rows break at iPad portrait (768–820px).** `css/pos.css:472` makes rows 6 columns; fixed columns eat ~246px (emoji 28 + qty pill 82 + price 46 + note 26 + remove 24 + 5×8 gaps) but the 290px cart (`pos.css:1265`) minus list padding (`pos.css:1268`) leaves 258px — the item name (1fr, no ellipsis, `pos.css:525`) gets ~12px → CJK names wrap one character per line. Title row also overflows once 取单(n) appears (`js/pos.js:351-353`; ~317px of buttons+title, no flex-wrap `pos.css:372`). → At ≤820px: two-line cart rows (note btn under name) + `flex-wrap` on title row + ellipsis on `.pos-ci-name`.

2. **New note button creates a mis-tap trap next to remove.** Note btn is 26×26 (`pos.css:485`), remove × is 20×20 (`pos.css:543`), 8px apart — both far under the 44px iPad minimum. Aiming for 备注 and hitting × silently deletes the line (no undo). → ≥40px hit areas (transparent padding) and put a gap or divider between them.

3. **Staff roster field splits ASCII comma only.** `js/settings.js:234-235` `split(',')` — an owner typing with a Chinese IME enters `，`, so "Qian Min，Tock Chau" saves as ONE staff name and the void-attribution dropdown (`js/orders.js:399-404`) is silently wrong. → `split(/[,，、]/)`.

## ⚠️ Important polish

1. Cancelled PIN destroys the discount modal + all entered state (`js/pos.js:806-814`, comment admits it) — a manager PIN typo + Cancel forces re-entering mode/value/reason. Reopen the discount modal with prior state.
2. No way to remove a manager PIN once set — blank keeps it (`js/settings.js:161,239-246`). Add 清除 PIN.
3. Offline banner (`css/style.css:151`, z-400) overlays the fixed 64px navbar (`style.css:80-82`), covering the top of nav tabs while offline. Offset it below the navbar.
4. PIN input focuses via `setTimeout(60)` (`js/app.js:185`) — outside the tap gesture, so the iPad keyboard won't auto-raise; cashier taps twice. (Note prompt is fine: sync focus, `app.js:94-96`.)
5. Held orders are per-device localStorage (`js/pos.js:99-100`) — invisible on a second iPad and stale ones linger; show age in the 取单 list.
6. Reprint replaces the detail modal (`js/orders.js:560-564`); closing the receipt strands the cashier — return to detail. Also `btn-sm` beside full-size 关闭 (`orders.js:546-547`).

## 💡 Nice-to-have

1. `title=` tooltips on note/hold buttons (`js/pos.js:315,352-353`) never show on touch; icon-only 备注 is undiscoverable — first-run hint or text label.
2. Recall-blocked toast is CN-only (`js/pos.js:577`) — rest of flow is bilingual.
3. 挂单/取单/清空 are ~26px tall (`pos.css:499`) — bump toward 40px.
4. `.rcpt-item-note` 0.74rem isn't bumped by the thermal print rules (`pos.css:1245` vs `1297-1306`) — set 11-12px explicit.

## ✅ What's working well — max 3

1. `GC.prompt` over native `prompt()`: styled modal, `\n`→`<br>` renders the 少糖/去冰 example line correctly (`js/app.js:74`), OS keyboard works.
2. Offline block is CSS-only `pointer-events` (`css/style.css:158-163`) — hold/recall stay usable offline; view-level disabled states survive reconnection.
3. Bilingual microcopy is clean; the PIN hint「已设置 — 输入新 PIN 可更换；留空保持不变」(`js/settings.js:161`) is exemplary.
