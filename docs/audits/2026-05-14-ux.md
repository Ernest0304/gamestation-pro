# UX Audit — 2026-05-14 (logo + branding swap)

Scope: commit `5ebaeff` — placeholder removed, `郁香潭 / Yuu Xiang Dam` brand
applied to navbar, login, favicon, PWA manifest.

## ⭐ Critical — max 3

1. **PWA theme color disagrees with HTML `<meta>` theme color** — `index.html:6`
   sets `theme-color="#06b6d4"` (cyan) but `manifest.json:8` sets
   `"theme_color": "#7a0818"` (brand red). On install the status bar will flip
   color between browser-loaded and standalone PWA. → pick one (recommend the
   red `#7a0818` for brand consistency in both files).

2. **Logo SVG is far too detailed for 44 px navbar / 16 px favicon** —
   `gaming-cafe/img/logo.svg:51` arc text at `font-size: 9.5` and
   `gaming-cafe/img/logo.svg:22-28` petal ellipses become sub-pixel noise when
   the 240×240 viewBox is rasterized to 44 px (and unreadable at 16 px favicon
   `index.html:13`). → ship a simplified favicon variant (just the white circle
   + `香`) and keep the full logo for ≥100 px contexts only.

3. **Apple touch icon points at SVG** — `index.html:14`
   `apple-touch-icon` href = `/img/logo.svg`. iOS Safari does not honor SVG for
   the home-screen icon and will fall back to a low-quality screenshot of the
   login screen. → export a 180×180 PNG (`apple-touch-icon.png`).

## ⚠️  Important polish — max 6

1. **POS-mode loses the logo's white outer ring** — `logo.svg:11` is `#ffffff`
   on a dark navbar (good contrast), but POS-mode navbar is cream `#fffbf3`
   (`pos.css:19`). Ring vanishes against cream and the disc looks unbordered.
   → add a subtle stroke or 1 px box-shadow on `.nav-logo` in `body.pos-mode`.

2. **Redundant brand text on login** — `auth.js:14` shows the 100 px logo
   (which already contains `郁香潭 · YUU XIANG DAM`) and `auth.js:15` repeats
   `郁香潭 · Yuu Xiang Dam` immediately below. → drop the `<h1>` or replace it
   with a tagline.

3. **Stale POS-mode selectors** — `pos.css:23-31` targets
   `.nav-brand .brand-accent` and `.nav-brand svg`, neither of which exist in
   the current markup (`brand-accent` lives on the login `<h1>` only; the
   navbar uses an `<img>`, not inline SVG). → delete or rewrite to target
   `.nav-brand-zh` / `.nav-brand-en`.

4. **`html lang="zh-CN"` for a Singapore shop** — `index.html:2`. → set to
   `zh-Hans-SG` or `en-SG` so iOS/Android pick the right system font fallback.

5. **Brand text + bilingual nav links compete for hierarchy** —
   `style.css:66-75`: `.nav-brand-zh` is 1.05 rem 700 weight, while
   `.nav-link` (`style.css:85`) is 0.875 rem 500. The brand block already
   carries Chinese + English; the nav links repeat the pattern. Reads busy at
   44 px. → consider hiding `.nav-brand-en` above 1024 px to lighten the
   left-hand stack.

6. **Mobile (<640 px) hides nav-brand entirely** — `style.css:730`
   `.nav-brand { display: none; }`. On iPhone staff get no brand cue inside
   the app (only when not logged in). → either keep a 28 px logo-only mark at
   top-left, or accept this for the bottom-tab layout and document it.

## 💡 Nice-to-have — max 4

1. **Drop-shadow on `.nav-logo`** uses brand red `rgba(122,8,24,0.25)`
   (`style.css:61`). On the dark navbar this reads as a faint glow; on POS
   cream it disappears. Tune per mode.

2. **Favicon variants** — add `favicon-32.png` and `favicon-16.png` PNG
   fallbacks alongside the SVG so older Safari and pinned-tab Chrome get
   crisp marks.

3. **Manifest is missing maskable icon** — `manifest.json:9-14` ships one SVG
   only. Android adaptive-icon will hard-crop the round disc. Add a maskable
   PNG with safe-zone padding.

4. **`Brush Script MT` "Dessert" word** (`logo.svg:47`) is a macOS-only font.
   On non-Apple devices it renders as default serif italic. Convert to path
   or use a web-font.

## ✅ What's working well — max 3

1. Bilingual nav with emoji + 中文 + EN abbreviation (`index.html:27-33`) is
   tired-cashier-friendly: glanceable in either language.
2. POS-mode color mapping for `.nav-brand-zh` to `#7a0818`
   (`style.css:78`) means the brand actually reads correctly in light mode —
   not just a copy-paste of dark styles.
3. 44 px navbar logo is a sensible touch target and the `gap: 12px` between
   logo and text (`style.css:56`) gives breathing room.

## 📝 Note for Ernest (owner)

Branding direction is right, but **not go-live-ready** yet — the theme-color
mismatch and Apple-touch-icon SVG will cause visible glitches on installed
devices, and the logo will look fuzzy at navbar/favicon sizes. A simplified
favicon variant + PNG touch-icon + fixing the manifest/meta theme-color trio
gets this shippable in under an hour.
