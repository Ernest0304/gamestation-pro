# UX Audit — Full state (commit 61e15f0)

Scope: POS, Gaming dashboard, Orders, Menu admin, Members, Settings,
History, Login, all modals. Not a re-flag of prior audits.

## Critical (blocks daily use) — max 4

1. **"GameStation Pro" still in customer-facing reports** —
   `js/history.js:184` (PDF title), `:236` (Excel summary row), `:224` +
   `:279` (filenames `GameStation-Report-...`). Brand swap missed reporting.
   Replace with `郁香潭 · YXD` + filename prefix `YXD-Report-`.

2. **Dashboard "Idle" count is hardcoded to 6 stations** —
   `js/dashboard.js:202`: `${6 - activeCount}`. Add or remove a station and
   this goes wrong (or negative). One-line fix:
   `${stations.length - activeCount}`.

3. **POS search input loses focus & value on every cart change** —
   `js/pos.js:81–97` does full `innerHTML` rewrite on every add/dec, and
   `pos-search` (`:144`) has no `value=` binding. Cashier types "杨枝",
   taps a card to add it, the search clears. `pos-guest-name` (`:195`)
   keeps its value via the module var but cursor jumps to end on every
   keystroke. Single biggest daily-use friction.

4. **`GC.confirm` Enter listener is document-scoped** — `js/app.js:55–59`
   binds `keydown` on `document`. While confirm is open, Enter anywhere
   triggers OK. Blast radius small today (one modal at a time), but if cash
   or discount modal ever stacks a confirm, Enter on the number input fires
   the wrong action. Scope the listener to the modal element.

## Important polish — max 8

1. **Promo banner hardcodes station-type keys** — `js/dashboard.js:191,193`
   reads `rates.promo['Switch 2']` literally. Drift the key in settings and
   the banner silently shows `$undefined/h`. Iterate over `Object.keys`.

2. **Discount modal has 3 input affordances stacked** — `js/pos.js:441–467`
   shows an `<input>`, 6 quick-buttons, AND a numpad. On a 768px iPad the
   modal body scrolls so the numpad is below the fold. Pick numpad OR
   quick-buttons.

3. **Receipt modal has no auto-close or "next order"** —
   `js/pos.js:844–846`. Cashier must click 关闭 to return to POS. Add a
   primary "下一单 / Next Order" button.

4. **Voided order rows use strike-through on Chinese glyphs** —
   `css/pos.css:1022` applies `text-decoration: line-through` to the whole
   `<tr>`. The line runs through the middle of CJK characters, making them
   harder to read than the original. Use a dimmed bg + badge.

5. **`tier-badge.regular` is invisible on dark cards** —
   `css/style.css:389` uses `rgba(100,116,139,0.15)` on `bg-card`. Add a
   1px outline so it's distinguishable from "no badge at all".

6. **History PDF/Excel header colour is cyan** — `js/history.js:221`
   passes `fillColor: [6,182,212]`. On a white-page export, the brand red
   `[122,8,24]` would match the rest of the system.

7. **Settings page mixes "Save" with "Reset All"** —
   `js/settings.js:163–165`. Three peer buttons; destructive Reset has
   typed confirmation but no visual hierarchy. Move Reset to a "Danger
   zone" block at the bottom.

8. **POS rebuilds full menu DOM on every quantity tap** — `js/pos.js:81`.
   Not broken, visibly jittery on slower iPads. Split `renderCartPanel` so
   cart updates in isolation.

## Nice-to-have — max 5

1. **Login forgets last email** — `js/auth.js:20`. Persist last-used email
   in `localStorage`; saves seconds per shift change on a shared iPad.

2. **Toast duration fixed at 2.5s** — `js/app.js:117`. Long error messages
   (`结账失败: row violates RLS...`) flash by. Scale duration with length,
   or pin errors until tapped.

3. **`.brand-accent` is dead code** — `css/style.css:81`. No live caller
   after the logo-redraw audit; drop the rule.

4. **POS 清空 and member 重新生成 buttons look like links** —
   `js/pos.js:208`, `js/members.js:184`. Confirm protects them, but the
   visual affordance should signal danger (amber outline).

5. **Receipt timestamp uses `zh-CN` locale** — `js/pos.js:800` calls
   `toLocaleString('zh-CN')`. SG convention is 24h `YYYY-MM-DD HH:mm`;
   `zh-CN` gives `2026/5/14 下午4:40`. Switch to `zh-Hans-SG` or `sv-SE`.

## What's working well — max 3

1. **Cash modal change calculator** — `js/pos.js:705–711` smart presets
   (exact + nearest $5/$10/$20/$50/$100) with live insufficient/change
   feedback. Shipping-quality.

2. **Time-up alert system** — `js/dashboard.js:91–171`. Sound + title-flash
   + browser notification, with warned-IDs persisted across F5. Will catch
   tired staff reliably.

3. **POS light-mode via single `body.pos-mode` class** — `js/app.js:130`.
   Clean architecture; new modals inherit the right theme without
   per-component work.
